# 2.7 Data drift deep dive (optional)

## Methods in detail

- **Parametric tests** (Z-test, T-test) – assume a distribution shape. Most sensitive → small data, critical cases (healthcare). Hard to tune across many mixed features.
  - one-sample: no reference, test against a hypothesis ("mean age ≈ 35")
  - two-sample: compare against reference
- **Non-parametric tests** (K-S, Anderson-Darling, chi-squared, Fisher/Barnard exact) – few assumptions, easy to pick by feature type. Less sensitive. Best under ~1000 rows.
- **Distances** (Wasserstein, Jensen-Shannon, PSI) – easy to interpret ("moved by 0.2 std"). Best over ~1000 rows. On big data p-values flag tiny, meaningless shifts.
- **Domain classifier** – train a model to tell reference from current. If it can (ROC AUC high), data drifted. Works for text, embeddings, mixed data.

## Choosing

1. **Start with defaults** – e.g. Wasserstein with threshold 0.1, monitor, then tune based on false alarms.
2. **Test on history** – take a stable period and a period with known (or synthetic) drift. Keep the setup that catches real drift with fewest false alarms. Try tests, thresholds, window sizes.

## Special cases

- **Large data** – sample, or bucket (hourly instead of per minute).
- **Real-time** – drift needs batches: use a moving window, with fixed or moving reference.
- **Drift ≠ retrain trigger.** New data can be bad, too small or unrepresentative (pandemic, holiday). Use drift to trigger **investigation or labeling**, evaluate before shipping a retrained model.

## Reading data + prediction drift together

| Data drift | Prediction drift | Good reading | Bad reading |
|---|---|---|---|
| yes | no | model is robust | model ignores an important change |
| yes | yes | model reacts as it should | model behaves strangely |

## When drift is detected

1. **Check data quality** – stale or broken features look like drift.
2. **Investigate** – which features, how much, which segments, real-world cause, ask domain experts.
3. **Do nothing** – false alarm, or model handles it.
4. **Act** – retrain with new labels, rebuild the model, tune thresholds, or fall back to a non-ML rule.
