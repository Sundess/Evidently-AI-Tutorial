# 2.6 Data and prediction drift

When labels are missing or delayed, you can't measure quality. Drift is the proxy.

- **Prediction drift** – the distribution of model outputs changes. Best single proxy: *if you monitor one thing, monitor the outputs.*
- **Feature (data) drift** – the distribution of inputs changes. Early warning and a debugging aid.
- **Concept drift** – the relationship between inputs and target changes (not covered here).

## Things to keep in mind

- Drift is a **heuristic** – no objectively right answer, depends on the use case.
- Not all drift hurts quality. Important features matter more.
- Useful even with labels – feature drift often shows up before quality drops.
- Most valuable for important models with delayed feedback.

## Decisions to make

1. **Method** – statistical test, distance metric, or rule.
2. **Threshold** – p-value or distance cut-off.
3. **Reference** – what "normal" looks like.
4. **Alert condition** – e.g. share of drifted features, or drift in top features only.

## Methods

| Type | Examples | Score | Good for |
|---|---|---|---|
| Statistical test | K-S, chi-squared | p-value (drift if **below** threshold) | small data |
| Distance | Wasserstein, Jensen-Shannon, PSI | distance (drift if **above** threshold) | large data |
| Rule | "new category appeared" | custom | known expected changes |

**Evidently defaults**

- ≤ 1000 rows: K-S (numerical), chi-squared (categorical), Z-test (binary). Threshold 0.05.
- \> 1000 rows: Wasserstein (numerical), Jensen-Shannon (categorical). Threshold 0.1.

## Univariate vs multivariate

- **Univariate** – one test per feature. Easy to interpret.
- **Multivariate** – one answer for the whole dataset (PCA, domain classifier).
- Middle ground: **share of drifted features** (Evidently flags dataset drift when ≥ 50% drift), or only top features.

## Tips

- Check data quality first.
- Pick methods per feature type and importance.
- Monitor clear segments separately.
- For prediction drift, don't use training rows as reference – predictions on them are overconfident and any new batch looks drifted. Use a validation set or a past production batch.
